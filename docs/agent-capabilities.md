# Agent 能力与边界

记录 2026-06 桌面端 + agent 这一批能力,以及容易被忘记的**安全边界**。

## 子代理（spawn_agent）

主代理可用 `spawn_agent({ task })` 把一个独立子任务派发给**隔离的只读子代理**:它继承同一工作区和操作规则,用全新的聚焦上下文调研/生成,把产出(代码片段/文本/JSON)作为文本返回给主代理(上下文隔离,主对话不被探索细节撑爆)。

- **只读(single-writer 架构)**:子代理只能 `read_file` / `list_dir` / `grep` / `echo`,**不能写文件或执行命令**。所有子代理返回片段后,由**主代理统一汇总、独占写入**目标文件——并发竞争从架构上消失,不依赖文件锁。不要让子代理「写文件 X」,而是让它「产出 X 的内容」、你来写。
- **深度上限 1**:子代理拿不到 `spawnSubagent`,再调 `spawn_agent` 会被拒绝(防递归)。
- **代码扇出按文件粒度**:让每个子代理产出**一个完整文件**的内容、主代理原样写入(文件内部自洽)。**不要**把一个代码文件拆成片段让多个子代理各写一段再硬拼——孤立片段不共享 import/类型/签名,拼出来不能编译。必须互锁的部分:要么放一个子代理,要么主代理先定好接口契约写进每个子任务。
- **拼装后必须校验**:子代理不能跑命令,所以主代理写完代码后要自己 `read_file` + 跑测试/编译/lint 验证。纯文本/独立章节可直接拼接。
- **步数上限**:子代理步数被压到 ≤20。
- 共享主代理的取消信号:停止主任务会一并停掉子代理。
- UI:子代理以 `🤖 子代理` / `✓ 子代理完成` 卡片呈现;只透传其 status 进度,不灌爆主时间线。

## 并行执行

一个助手回合里模型返回的多个工具调用,按「逐段处理」执行:

- **可并行(并发执行)**:`read_file` / `list_dir` / `grep` / `echo`(只读,无副作用)+ `spawn_agent`(隔离 + 路径锁保护)。一段连续的可并行调用用 `Promise.all` 同时跑。
- **串行(单独跑完才继续)**:`write_file` / `write_patch` / `run_command` / `move_file` / `rename_file` 等直接写类工具。保留主回合内的读-写顺序语义。
- 工具结果消息**严格按调用顺序**回填,与完成先后无关。

### 并发写安全 —— 重要边界

| 写入方式 | 是否受保护 | 说明 |
|---|---|---|
| `write_file` / `write_patch` / `move_file` / `rename_file` | ✅ 受**按路径写锁**保护 | 整段「读-改-写」原子化:同一文件的并发写自动串行、不损坏;不同文件真并行。兜底防护(子代理已只读,主回合内的写也本就串行)。 |
| `run_command` 内脚本自己的文件 I/O | ❌ **不受保护** | 对工具层是黑盒。若**主代理**并行跑脚本往同一/共享文件追加会丢数据(实测可达 88%~100%)。子代理已不能执行命令,不涉及此风险。 |

**single-writer 架构(已落实)**:子代理只读、返回片段,只有主代理写文件——所以并行子代理之间**根本没有写竞争**。上表的路径锁是主代理自身写入路径的防护(以及未来任何直接并发写的兜底)。

> run_command 的子进程文件 I/O 仍不受工具层保护;但子代理已**不能**执行命令,这条风险主要存在于主代理自己并行跑脚本时——避免让并行命令往同一文件追加。

## 命令执行确认（run_command）

- 设置 → 勾选「执行命令前确认」(`ui.confirmCommands`)后,每次 `run_command` **暂停等待**用户在卡片上选择:**拒绝 / 允许一次 / 本会话总是允许**。
- 「本会话总是允许」后该会话不再询问(到 daemon 重启为止)。
- **默认关闭**。自动化/渠道运行(无人值守)自动旁路。注意:`autoApplyPatches`(自动应用补丁)**不**影响命令确认,二者解耦。

## 检查点 / 回滚

- 每轮运行前对工作区打一次快照(游离 git commit,挂在 `refs/forge/checkpoints/` 下防 gc,保留 200 个 / 30 天),并入库,按用户轮次序号锚定。
- 悬停某条用户消息 → 「⟲ 回到此处」,可选:
  - **仅回滚文件**:工作区文件还原到该消息之前,对话保留。
  - **文件 + 撤回对话**:文件回滚 + 把该轮及之后的对话从库里删掉,时间线重建。
- 前提:项目是 **git 仓库**;会话执行中拒绝回滚;压缩历史(`/compact`)会清空检查点(轮次序号会平移)。

## daemon 生命周期

- **单实例锁**:启动时 ping 现有 socket,有活体 daemon 就退出,避免多开互踩。
- **构建不匹配**最多重启一次:若磁盘 daemon 比运行中的 app 新,重启一次后接受,不再无限循环。
- `FORGE_DAEMON_BUILD` 每次改 daemon 逻辑时 bump,桌面端据此重启过期 daemon。
