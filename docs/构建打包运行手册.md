# Forge Agent 构建/打包/运行手册

本文档用于团队内部快速上手 `forge-agent` 的构建、打包、运行与验证。

## 1. 环境要求

- Node.js: `>=22`
- 包管理器: `pnpm`（若本机无 pnpm，可使用 `npx pnpm@9`）
- 系统: macOS、Linux、Windows（CLI + Daemon 已支持；Desktop 可用 electron-builder 打安装包）

建议先检查：

```bash
node -v
pnpm -v
```

若没有 pnpm：

```bash
npm install -g pnpm@9
```

### Windows 快速验证

```powershell
pnpm install
pnpm build
pnpm smoke:win          # 或: pwsh -NoProfile -File scripts/smoke-test.ps1
pnpm forge init
pnpm start:daemon       # 终端 1
pnpm forge ping         # 终端 2
```

依赖：`Node.js 22+`、`git`、可选 `ripgrep`（`winget install BurntSushi.ripgrep.MSVC`）。

## 2. 项目结构与核心产物

- CLI 可执行入口: `apps/cli/dist/cli.js`
- Daemon 可执行入口: `apps/daemon/dist/main.js`
- 根级 bin 映射：
  - `forge` -> `./apps/cli/dist/cli.js`
  - `forge-daemon` -> `./apps/daemon/dist/main.js`

## 3. 安装与构建

在项目根目录执行：

```bash
cd /path/to/forge-agent
pnpm install
pnpm build
```

构建成功后可得到 `dist` 产物，CLI 与 Daemon 都可以直接运行。

## 4. 配置模型（API Key / URL / Model）

初始化配置文件：

```bash
pnpm forge init
```

默认配置路径：

- `~/.forge-agent/config.json`

示例配置（仓库根目录，复制到 `~/.forge-agent/config.json`）：

| 文件 | 说明 |
|------|------|
| `config.example.json` | 多厂商 profiles（OpenAI / DeepSeek / DashScope） |
| `config.deepseek.example.json` | 默认 `activeProfile: deepseek` |

```bash
cp config.example.json ~/.forge-agent/config.json
# 编辑 profiles.*.apiKey
```

切换厂商（不改文件手切）：

```bash
forge model list
forge model use openai gpt-4o-mini
forge model use deepseek deepseek-v4-pro
```

也可命令行改当前档的字段：

```bash
pnpm forge config set model.apiKey "<YOUR_API_KEY>"
pnpm forge config set model.name gpt-4o-mini
```

查看当前生效配置（API Key 脱敏）：

```bash
pnpm forge config show
```

## 5. 运行方式

### 5.1 标准双终端运行（推荐）

终端 1（启动 Daemon）：

```bash
cd /path/to/forge-agent
pnpm start:daemon
```

终端 2（CLI）：

```bash
cd /path/to/forge-agent
pnpm forge ping
pnpm forge
```

说明：

- `pnpm forge`：进入交互式聊天（类似 Claude Code）
- `pnpm forge run "任务" --cwd <项目路径>`：单次任务模式

### 5.2 交互模式（REPL）

```bash
pnpm forge
```

常用斜杠命令：

- `/help` 查看帮助
- `/exit` 退出
- `/clear` 新会话
- `/cwd` 查看当前工作目录
- `/cwd <path>` 切换工作目录
- `/session` 查看当前 session id

### 5.3 单次任务模式

```bash
pnpm forge run "用 echo 工具说 hello" --cwd .
pnpm forge run "执行测试并总结失败原因" --cwd /path/to/project
```

## 6. 打包与发布（CLI）

当前项目是 Node CLI 形态，常用“打包/发布”方式如下：

### 6.1 本机全局可执行（推荐）

```bash
cd /path/to/forge-agent
pnpm link:global
```

完成后任意目录可执行：

```bash
forge
forge run "任务描述" --cwd /path/to/project
```

取消全局链接：

```bash
pnpm unlink --global
```

### 6.2 不做全局 link，直接用 node 启动

```bash
FORGE=/path/to/forge-agent
node $FORGE/apps/daemon/dist/main.js
node $FORGE/apps/cli/dist/cli.js run "说 hello" --cwd .
```

### 6.3 Desktop 安装包（electron-builder）

桌面端会把 daemon 打进 `resources/daemon`，启动时用 Electron 自带的 Node（`ELECTRON_RUN_AS_NODE`）拉起后台进程。

**本机打包（先 `pnpm install`）：**

```bash
# macOS → release/Forge-<version>-mac-<arch>.dmg
pnpm pack:desktop:mac

# Windows → release/Forge-<version>-win-<arch>.exe（需在 Windows 上执行）
pnpm pack:desktop:win

# 仅生成未安装目录（调试用，较快）
pnpm pack:desktop:dir
```

说明：

- `prepare:bundle` 会构建 daemon 依赖树、`pnpm deploy` 到 `.electron-staging/daemon`，并对 `better-sqlite3` / `node-pty` 做 Electron ABI 重编译。
- Windows 安装包需在 Windows 环境打包（CI 的 `desktop-pack` job 会在 `windows-latest` 上产出 `.exe`）。
- 代码签名与公证未配置；分发前需自行接入 Apple / Authenticode 证书。

## 7. 快速验证（Smoke Test）

```bash
cd /path/to/forge-agent
pnpm smoke
pnpm eval    # 需 daemon + apiKey；先 ping，再跑 2 条轻量 run
```

该脚本会自动执行：

1. install + build
2. init config
3. 启动 daemon
4. ping 连通性检查

## 8. 运行策略与限制

- Agent 可调用内置工具：`read_file` / `grep` / `write_file` / `write_patch` / `run_command` / `memory_*` 等。
- **新建文件**优先 `write_file`；**改已有文件**用 `write_patch`。
- `run_command` 仅允许白名单命令（含 `python3`、`node`、`npm run dev` 等）。
- `write_patch` 默认会确认；使用 `-y` 可自动应用 patch；应用前会做 dry-run 校验。
- 应用成功后 REPL 打印 **How to run**；输入 **`/run`** 可执行建议命令。
- 聊天里可用 `@src/Foo.java` 把文件带入上下文。
- 内置 Skill（`skills/*.md`，含 `greenfield-app` 贪吃蛇/从零开发），按关键词自动匹配。
- **Ctrl+C**：REPL 执行中按一次取消当前任务（daemon `cancel_run`）。
- **本地读写**：默认使用内置 `read_file` / `write_patch` / `write_file`（不自动启动 filesystem MCP）。
- **MCP（可选）**：在 `~/.forge-agent/mcp.json` 中配置外部 MCP（数据库、浏览器等）；连接池复用，空闲 5 分钟回收。
- **会话 token 预算**：默认 `limits.maxContextTokens` 64000，超出时截断旧消息并提示 `⚠`；可用 `FORGE_MAX_CONTEXT_TOKENS` 覆盖。
- Memory 存在 `~/.forge-agent/data.db`，可用 `memory_search` / `memory_save`。

### MCP 配置（可选）

复制示例并按项目改路径：

```bash
cp mcp.json.example ~/.forge-agent/mcp.json
# 编辑 filesystem 的 args 最后一项为你的项目绝对路径
```

重启 daemon 后，日志应出现 `loaded N MCP servers`。

|------|------|
| 上下文 | @ 文件、git diff、关键词 grep 检索 |

## 9. 常见问题排查

### 9.1 `connect ENOENT ...daemon.sock`

原因：Daemon 未启动。  
处理：

```bash
pnpm start:daemon
pnpm forge ping
```

### 9.2 `Model API key not set`

原因：未配置 key 或被环境变量覆盖。  
处理：

```bash
pnpm forge config show
pnpm forge config set model.apiKey "<your-key>"
```

### 9.3 429 / 配额不足

原因：模型服务账号额度不足。  
处理：更换可用 key 或服务商；确认 `baseUrl/model/apiKey` 一致。

### 9.4 改了 config 但不生效

处理：重启 daemon（停止后重新 `pnpm start:daemon`）。

### 9.5 没有 `rg`

处理：

```bash
# macOS
brew install ripgrep

# Windows (PowerShell)
winget install BurntSushi.ripgrep.MSVC
# 或: choco install ripgrep
```

## 10. 运维建议

- 发布前固定执行：
  - `pnpm build`
  - `pnpm smoke`
- 生产环境建议固定：
  - Node 版本

  - Daemon 启停方式（systemd/launchd 可后续接入）

## 11. Forge 桌面端

构建与启动（需先 `pnpm build`）：

```bash
pnpm --filter @forge/daemon --filter @forge/desktop run build
pnpm --filter @forge/desktop start
```

若顶部提示「preload 未加载」，说明 `dist/preload.cjs` 缺失或过期，在 `apps/desktop` 下重新执行 `pnpm run build`（preload 须编译为 CommonJS，不可仅用 ESM 的 `preload.js`）。

行为说明：

- 渲染进程仅通过 `preload` 暴露的 `window.forgeDesktop` 与主进程通信（`contextIsolation` 已启用）。
- 主进程会在 daemon 未响应时自动拉起进程，并通过 PING 轮询等待就绪（最长约 8s）。
- 若 daemon 版本过旧导致 RPC 报错（如 `Unknown method: list_skills`），桌面端会对部分接口自动重启 daemon 并重试。
- 默认项目工作目录为系统「文稿」目录；可在「新增项目」中用「选择目录」指定路径。
- Skills 页支持搜索；MCP/插件/Skills 加载失败时可点「重试」。补丁事件可在右侧栏点击「应用补丁」。
